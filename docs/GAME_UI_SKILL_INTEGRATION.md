# color king 游戏 UI Skill 融合规范

状态：评审草案  
适用引擎：Godot 4.7  
设计基准：竖屏 `540 × 960`  
最后更新：2026-08-11

## 1. 文档定位

本文档把以下四个开发 Skill 的方法融合进 `color king` 的产品、UI 和工程流程：

- `game-ui-ux`：页面结构、响应式布局、安全区、页面流和事件驱动 UI。
- `godot-ui-control`：Godot `Control`、Container、Theme、焦点和输入实现。
- `godot-animation`：`AnimationPlayer`、Tween 的选择、生命周期和组合方式。
- `performance-optimization`：基于真机测量的帧预算、内存分配和资源预算。

本文档不是新的产品事实源。发生冲突时，按以下优先级处理：

1. 用户当前明确要求。
2. [`PRODUCT_REQUIREMENTS.md`](PRODUCT_REQUIREMENTS.md) 的玩法和产品约束。
3. [`UI_DESIGN_GUIDE.md`](UI_DESIGN_GUIDE.md) 的视觉规范。
4. 本文档定义的实现和验证方式。
5. 四个 Skill 的通用示例和默认值。

Skill 中的示例不能覆盖以下项目硬约束：皇冠规则、正式 Hint 只能引导画普通 X、明亮经典色板、区域黑色边界、统一本地化入口、存档及经济规则。

## 2. 融合目标

融合后的 UI 开发应同时满足四个结果：

- **结构稳定**：页面在目标手机、安全区、长文本和 RTL 环境中不裁切、不遮挡。
- **状态清楚**：玩法状态由 Controller/Rule/Service 产生，页面只消费语义化数据和事件。
- **动画可控**：动画增强反馈，但不成为金币、棋盘或页面状态的事实源。
- **性能可验证**：不以“应该更快”为结论，必须在 Pixel 真机 Release 包中记录前后指标。

## 3. 四个 Skill 的职责边界

| 层级 | 主 Skill | 在本项目中的职责 | 禁止越界 |
| --- | --- | --- | --- |
| 体验结构 | `game-ui-ux` | 页面信息层级、响应式布局、安全区、页面栈、焦点、事件驱动 HUD | 不直接决定 Godot 节点细节，不修改玩法规则 |
| Godot UI | `godot-ui-control` | `Control`、Container、Anchor、Theme、`mouse_filter`、焦点导航 | 不实现棋盘规则，不决定动画节奏 |
| 动画实现 | `godot-animation` | 为固定时间轴和一次性反馈选择 `AnimationPlayer` 或 Tween，管理取消与复位 | 不把 Tween 中间值写成业务事实，不改变结算数值 |
| 性能治理 | `performance-optimization` | 定义复现步骤、测量 CPU/GPU/内存、定位最大瓶颈、复测 | 不凭猜测删除效果，不在无数据时进行复杂微优化 |

组合关系固定为：

```text
产品规则 / Controller 状态
          ↓
game-ui-ux：决定页面如何表达
          ↓
godot-ui-control：决定节点如何布局和响应输入
          ↓
godot-animation：决定反馈如何播放、取消和复位
          ↓
performance-optimization：在真机上测量并约束成本
```

## 4. 当前项目基线与差距

### 4.1 已经对齐的部分

- `project.godot` 已使用 Godot 4.7、`540 × 960` viewport 和 `canvas_items` stretch。
- 首页、正式关卡、拼块关卡和结果页已经拆入 `scripts/pages/`，符合页面与流程协调器分离方向。
- `scripts/controllers/`、`scripts/rules/`、`scripts/services/` 和 `scripts/storage/` 已承担玩法状态、规则、经济和存档职责。
- `scripts/ui_tokens.gd` 已提供颜色、棋盘、弹窗和提示视觉 token。
- `scripts/components/coin_roll_display.gd` 已作为顶部与结果页共用的金币显示组件。
- 页面主要使用 `Control` 和 Container，装饰层普遍使用 `MOUSE_FILTER_IGNORE`。
- 多语言统一由 `LocalizationController` 管理，产品已经覆盖中文、英语、阿拉伯语、法语和拉丁语。

### 4.2 后续需要收敛的部分

- 当前不少页面仍通过大量 `add_theme_*_override()` 分散定义字号、颜色和 StyleBox；共享样式应逐步沉淀为 Theme/样式工厂或扩展 `UITokens`，避免页面间漂移。
- 部分所谓 `safe_area` 目前只是固定 `MarginContainer`，尚未形成基于 `DisplayServer.get_display_safe_area()` 的统一运行时适配器。
- 现有 UI 主要针对单一竖屏基准，仍需验证窄屏、长屏、系统字体缩放、长翻译和 RTL。
- Tween 已分散在页面、弹窗和 Overlay 中；需要统一动画持有、取消、页面离开复位和减少动画策略。
- 金币飞入、花瓣和循环心跳等短生命周期视觉节点需要通过真机数据决定是否池化或限制并发。
- 性能验收尚需固定可重复场景、Release 真机采样方式和记录模板。

以上是迁移清单，不要求一次性重写所有页面。每次触达某个组件时，按本文档逐步收敛。

## 5. 布局与页面流规范

### 5.1 布局模型

- 以 Anchor 决定页面区域，以 Container 决定同一区域内的排列。
- 禁止在 Container 子节点上依赖手工 `position` 或 Anchor；Container 是其尺寸与位置的唯一管理者。
- 固定像素只用于设计 token，例如最小触控尺寸、边距、线宽和卡片圆角；不得以固定绝对坐标拼整页。
- 棋盘、拼块和特效需要自由坐标时，使用独立 `Control` 绘制层或 Overlay，不把自由定位节点直接放进排列 Container。
- 棋盘保持正方形并优先占据剩余空间；标题、说明和操作区不得无上限挤压棋盘。

### 5.2 竖屏与安全区

- `540 × 960` 是设计基准，不是唯一合法尺寸。
- 页面根节点保持 Full Rect；关键内容放入统一安全区容器。
- 冷启动、窗口尺寸或方向变化时重新应用系统安全区，不在 `_process()` 中每帧读取。
- 背景、花瓣和装饰光可延伸到屏幕边缘；返回、设置、金币、红心、按钮和关键文案必须位于安全区内。
- 关卡页为了最大化棋盘可使用较窄视觉边距，但顶部操作和底部道具点击区域仍须满足安全区与最小触控尺寸。

### 5.3 内容自适应

- 文案必须来自 `LocalizationController`，页面不得新增硬编码玩家可见文本。
- 文本和按钮优先由 Container 根据内容扩展，不能只按英文长度固定宽度。
- 金币、关卡号和奖励等数字组件至少验证 `0、8、18、99、108、999、1000、99999`。
- 阿拉伯语页面允许整体 RTL；金币图标与阿拉伯数字的组合组件保持明确的内部 LTR，避免图标和数字跳位。
- 文本状态不能只靠颜色表达；禁用、错误、提示、选中状态同时使用图标、轮廓、明度或形状。

### 5.4 页面状态与输入所有权

- `main.gd` 只负责模块装配、跨流程路由和事件编排。
- 页面通过 `present_*()`、`set_*()` 等语义 API 接收 ViewData，通过 signal 发出用户意图。
- 页面不得直接读取或修改金币、存档、答案和推荐模型。
- 弹窗或 Overlay 打开后成为顶部输入所有者，关闭后恢复之前的焦点或页面输入。
- 正式 Hint 蒙层、教程强引导和拼块过场锁定输入时，锁定原因由 Controller 状态决定，不能只依赖遮罩是否可见。

## 6. Godot Control 与 Theme 落地规范

### 6.1 节点选择

- 普通页面、HUD、按钮、标签和弹窗使用 `Control` 派生节点。
- HUD 和跨场景 Overlay 放在 `CanvasLayer/Control` 体系内，不使用 `Node2D` 模拟普通 UI。
- `VBoxContainer`、`HBoxContainer`、`GridContainer`、`MarginContainer` 和 `AspectRatioContainer` 分别负责排列、留白与棋盘比例。
- 横向拼块托盘使用 `ScrollContainer` 管理可滚动内容；拖动方块本体进入独立 Overlay 后再使用自由坐标。

### 6.2 样式来源

- `scripts/ui_tokens.gd` 是运行时语义 token 源，与 `UI_DESIGN_GUIDE.md` 同步维护。
- 页面共享的字体、按钮、Panel、焦点和禁用样式逐步迁入 Theme 资源或集中样式构造器。
- 页面内 `add_theme_*_override()` 只允许表达真正的局部状态，例如错误态、Hint 强调态和本次结算等级。
- 禁止在两个页面分别复制同一金币、按钮或弹窗 StyleBox。
- 棋盘色板和边界继续由棋盘视觉规范控制，不因 Theme 重构改变玩法识别。

### 6.3 输入和焦点

- 纯装饰 Full Rect 节点必须设置 `MOUSE_FILTER_IGNORE`，避免吞掉棋盘和按钮输入。
- 模态层使用 `MOUSE_FILTER_STOP` 并显式恢复底层输入。
- 每个页面和弹窗指定默认焦点；后续接入键盘/手柄时补齐明确的 focus neighbors。
- 触控目标保持至少 `48 × 48px`，小图标通过透明点击 padding 扩大触控区。
- 焦点样式与 Hover 样式分离，且不能只靠颜色变化。

## 7. 动画系统规范

### 7.1 工具选择

| 场景 | 推荐工具 | 原因 |
| --- | --- | --- |
| Splash、教程步骤、拼块压平等固定时间轴 | `AnimationPlayer` | 时间轴、信号点和资源可视化管理更稳定 |
| 按钮回弹、金币飞入、数字滚动、Toast 淡入淡出 | Tween | 一次性、参数化、由代码触发 |
| 当前 UI 页面 | 不使用 `AnimationTree` | 页面不存在需要混合的角色状态机；避免无必要复杂度 |

### 7.2 状态与动画分离

- 金币余额、皇冠、X、红心、拼块位置先由 Service/Controller 提交，再播放表现动画。
- 动画完成回调可以释放输入或进入下一视觉阶段，但不能决定交易是否成功、关卡是否通关。
- 动画被跳过、节点退出树或用户切页后，UI 必须能立即归一到最终业务状态。
- 禁止同时用 `AnimationPlayer` 和 Tween 写同一节点的同一属性。

### 7.3 Tween 生命周期

- 每个组件保存自己创建的长期或可重入 Tween 引用。
- 新动画开始前结束同一属性的旧 Tween；页面隐藏或退出时统一 `kill()` 并复位位置、缩放、透明度。
- 循环 Tween 必须有显式停止入口，例如红心跳动、教程手势和狮子待机动画。
- 与具体页面同生命周期的动画使用节点 `create_tween()`；只有明确需要跨页面存活时才使用 `get_tree().create_tween()`。
- 数字滚动以目标值为业务事实，视觉步数可压缩；不能为大额奖励创建与金币差值相同数量的节点或无限队列。

### 7.4 动效等级

- **一级反馈**：按钮按下、普通 X、合法拼块吸附。时长短，不阻塞下一次操作。
- **二级反馈**：提示光环、错误皇冠、金币消费、方块归位。允许短暂强调，但不循环闪烁。
- **三级反馈**：通关、Excellent、首次拼块转换、Splash。允许组合狮子、金币和花瓣，但必须提供稳定结束态。
- “减少动画”模式下取消回弹、飞行、闪光和循环动作，只保留淡入淡出与最终数值。

## 8. 性能预算与测量规范

### 8.1 测量原则

- 优化顺序固定为：复现 → Release 真机测量 → 判断 CPU/GPU → 修复最大瓶颈 → 同场景复测。
- 编辑器 Debug 结果只能用于定位，不能作为 Pixel 真机性能结论。
- 每次性能优化记录设备、APK 类型、关卡、操作步骤、帧时间、节点数、内存和改动前后结果。
- 没有测量收益的复杂优化应回退，避免仅增加维护成本。

### 8.2 初始目标预算

- Pixel 真机目标为稳定 `60 FPS`，单帧预算 `16.67ms`；低端设备允许另设 `30 FPS / 33.3ms` 档位。
- UI、动画和其它非玩法工作以约 `2ms` 的初始子预算为观察线，最终数值以真机基线调整。
- 静态 HUD 不使用 `_process()` 轮询金币、红心和进度，统一响应 signal。
- `_process()` 中禁止持续构造临时 Array、Dictionary 和格式化字符串。
- 频繁短生命周期节点先测量；确认实例化/释放造成尖峰后，再为金币、花瓣、Toast 等建立有上限的对象池。
- 同屏透明蒙层、花瓣、光环和飞行金币要关注移动端 overdraw；优先限制层数和可见数量。

### 8.3 代表性性能场景

至少保留以下可重复测试场景：

1. 冷启动到首页或教程，记录黑屏时长、首帧和峰值内存。
   - 运行时关卡目录使用离线二进制资源；普通关卡目录和拼块 manifest 可在启动阶段读取，当前适合分发的完整 size 优先发起异步加载，不能阻塞首页。只有恢复未完成拼块局时，才同步等待该局对应的 size。
   - 其它已解锁 size 在首页首帧后按顺序错峰后台加载；新 size 在解锁前两关发起后台预加载，禁止在 `_ready()` 中解析完整 `composite_levels.json`，也不把完整 size 再拆成多个运行时缓存分片。
2. 9x9 正式关卡开启 Hint 蒙层并连续滑动标记。
3. Hard 拼块关卡横滑托盘、拖动、吸附、撤回及死局判断。
4. 结果页 Excellent：狮子、金币飞入、数字滚动和花瓣同时播放。
5. 连续切换结果页、下一关和首页，检查残留 Tween、节点和内存增长。

## 9. 各页面的融合要求

| 页面/组件 | UI/UX 要点 | Godot 落地 | 动画与性能重点 |
| --- | --- | --- | --- |
| 首页 | 开始关卡最高层级；拼块次级；新人流程弱入口 | Anchor 分区 + VBox 按钮流；长文案自适应 | 只保留轻量品牌入场，不常驻循环 |
| 正式关卡 | 棋盘优先；顶部轻量；道具三等分 | `AspectRatioContainer`/等价正方形约束；Overlay 不吞输入 | Hint 重绘不改规则；避免每帧重建蒙层 |
| 拼块关卡 | 棋盘和托盘同时清楚；拖放可撤回 | `ScrollContainer` 托盘 + 独立拖动 Overlay | 拖动位置实时更新，但死局判断和复杂搜索不放入每帧 |
| 结果页 | 完成信息、狮子、余额、下一关层级明确 | 共用 `CoinRollDisplay`；Container 根据位数扩展 | 业务余额先确定；飞入和滚动可跳过、可中断、可归一 |
| 教程 | 与正式关卡保持位置记忆；当前操作唯一突出 | Overlay 锁定非目标输入；目标格仍使用统一棋盘坐标 | 手势循环必须在步骤改变时停止；支持减少动画 |
| 弹窗/设置 | 安全区内、自适应翻译、焦点封闭 | 统一 Dialog Controller + 内容 Container | 打开/关闭 Tween 不持有经济或存档状态 |

## 10. 开发流程

每个 UI 或交互任务按以下顺序执行：

1. 从 `PRODUCT_REQUIREMENTS.md` 确认产品事实和不可变玩法约束。
2. 在 `UI_DESIGN_GUIDE.md` 确认现有 token、页面层级和视觉状态。
3. 使用 `game-ui-ux` 定义页面结构、输入所有权、可访问性和 ViewData。
4. 使用 `godot-ui-control` 选择 Anchor、Container、Theme 和 `mouse_filter`。
5. 使用 `godot-animation` 定义工具、状态提交时点、取消和最终复位。
6. 先实现正确、可中断的版本，再用 `performance-optimization` 在真机测量。
7. 同步更新产品文档、UI 规范或本融合文档中的对应事实。
8. 运行自动测试，并完成目标分辨率、多语言和 Pixel 真机回归。

任务交付时至少说明：

- 修改了哪个页面或组件。
- ViewData/signal 是否变化。
- 动画是否可取消并恢复最终状态。
- 检查过哪些分辨率和语言。
- 性能问题是否真机测量；若未测量，不能宣称性能已经提升。

## 11. 回归矩阵

### 11.1 布局

- `540 × 960` Pixel 基准完整显示。
- 窄屏和更长竖屏无裁切、遮挡和棋盘变形。
- 顶部与底部关键操作位于系统安全区。
- `0、8、18、99、108、999、1000、99999` 金币余额完整显示。

### 11.2 本地化与可访问性

- 中文、英语、法语长文本不溢出。
- 阿拉伯语 RTL 下页面顺序正确，金币组件内部顺序稳定。
- 提示、错误、禁用和选中状态不只依赖颜色。
- 触控目标不小于 `48 × 48px`。
- 减少动画模式没有持续回弹、闪烁和大范围飞行。

### 11.3 动画

- Tween 中途切换页面后无残影、空白数字和输入锁死。
- 金币获得/消费动画结束后显示账户最终余额。
- 结果页重复进入不叠加狮子、金币或花瓣 Tween。
- Hint、教程和拼块过场结束后恢复正确输入范围。

### 11.4 性能

- 使用 Release APK 在 Pixel 真机测试代表性场景。
- 报告平均帧时间与明显尖峰，不只报告主观流畅度。
- 连续切页后节点数和内存不持续无界增长。
- 新增池化、缓存或批处理前后均有同场景数据。

## 12. 第一阶段落地建议

融合文档确认后，建议按以下顺序实施：

1. 建立统一 `SafeAreaContainer` 或等价页面适配器，并先覆盖首页、关卡页和结果页。
2. 梳理 `UITokens` 与重复 StyleBox，形成第一批共享 Theme/组件样式。
3. 为页面建立统一的 `stop_animations_and_normalize()` 生命周期接口。
4. 优先修正 `CoinRollDisplay` 的滚动卡顿，并用结果页复合动画做首个真机性能基线。
5. 补齐减少动画设置、长文本、RTL 和多余额位数回归。
6. 完成以上基础后，再扩展 Splash、更多粒子和复杂过场。

第一阶段不修改皇冠、Hint、拼块唯一解、经济或存档规则，只建立更稳定的 UI 与动画基础设施。
