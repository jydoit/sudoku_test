# 拼块关卡离线生成流程

## 当前阶段

本流程生成的 `data/composite_levels.json` 是拼块关卡事实源和 review 产物。Godot 正式运行时不直接解析该 JSON；发布前必须继续运行 `scripts/tools/build_runtime_level_bundles.gd`，生成轻量 manifest 和按 size 拆分的二进制运行目录。

```bash
/Applications/Godot.app/Contents/MacOS/Godot --headless --path . --script res://scripts/tools/build_runtime_level_bundles.gd
```

运行时先用 manifest 完成完整候选推荐，再优先异步载入当前适合分发的完整 size；其它已解锁 size 在首页首帧后错峰后台加载，下一 size 在解锁前两关预加载。只有恢复未完成的拼块局时才同步等待对应 size。运行目录按完整 size 划分，不再拆为多个缓存分片。JSON 解析、数值标准化、施工索引和方块候选落点计算只允许出现在离线构建流程。

入口：

```bash
python3 tools/generate_composite_levels.py
```

生成器完全由 Python 执行，不启动 Godot，也不导入或调用 GDScript。它直接读取输入 JSON 的棋盘尺寸、颜色区域矩阵和关卡 ID，在 Python 内完成施工区域选择、线索点选择、随机拆块、空间候选枚举、完整铺法搜索、皇冠唯一解求解和放置顺序生成，最后通过临时文件加原子替换写入结果。

## 输入和输出

默认输入为 `data/levels.json` 中所有方形且尺寸不小于 6×6 的关卡。`--levels` 也可以传入以下任一 JSON 结构，便于单关 review：

- `{ "levels": [...] }`
- `{ "level": {...} }`
- 单个关卡对象 `{ "levelId", "rows", "cols", "regions", ... }`
- 关卡对象数组 `[...]`

每个关卡分别生成：

- `simple`
- `medium`
- `hard`

默认输出为 `data/composite_levels.json`。每个条目包含：

- 原关卡 ID、难度和固化 seed；
- 施工颜色、线索格、施工格和全部拼块；
- 唯一获批的方块放置方案、最终颜色布局及其皇冠答案；
- `solutionOrder`：一条完整放置顺序，每一步保存方块、原点及当时空间候选数；
- 放置方案签名、颜色布局签名、全局搜索节点数和搜索空间是否耗尽；
- Hard 因原棋盘区域不足而降级为双区域时的 `difficultyFallback`。

运行时缓存字段不会写入 JSON，避免整数键在 JSON 中转换为字符串。

## 生成约束

每个候选依次经过以下检查：

1. 根据输入的 `regions` 矩阵统计颜色区域和相邻关系，按难度选择施工颜色。
2. 从安全边界格中排除割点，再按 `max(行异色格数, 列异色格数)` 选择线索格；最高分相同时按固化 seed 选择，不再追加同色邻居数等隐性二级评分。
3. 严格按 `ceil((可移动格数 / 2) × factor)` 拆块，`factor` 为 `0.5/0.6/0.8`。
4. 使用横竖条、2×2、L、T、S/Z 和异构模板切分；中间剩余空间允许暂时断开，但交付的每个块和最后剩余块都必须上下左右连通。
5. 每个拼块必须上下左右连通，初始拼块必须无重叠地完整覆盖施工区。
6. 每个颜色最多允许一个单位块兜底，不能用“整区一个大异形块”绕过目标块数。
7. 每个颜色区域拆出候选分区后，先独立执行一次小规模 Exact Cover。区域自身存在 0 个或 2 个以上最终摆法时立即重拆，不让多个低概率唯一分区拖到整局阶段才碰运气；3 次普通拆分失败后才间歇允许一个单位块兜底。
8. 同时建立两套候选：全施工区空间候选用于运行时吸附与难度指标；目标颜色候选只保留方块占格逐格属于其原始 `regionId` 的位置，用于离线唯一性证明。合法完整方案必须每块使用一次、不重叠、恰好填满施工区，并恢复输入文件的原始 `regions`。
9. 整局唯一性求解使用动态 MRV 的 Exact Cover 记忆化搜索。状态由占格位掩码、各视觉等价块组的剩余数量和候选下界组成，子问题结果截断为 `0/1/2+`；同颜色、同形状、同方向的视觉相同块使用递增候选下界消除内部编号交换。找到第 2 个合法完整放置方案时即可拒绝，只有未触及节点预算且完整搜索后仍为 1 个方案才能证明唯一。
10. 切分期对模板按目标区域内平移位置数量和重复形状次数降权；完整候选记录目标候选数、全空间候选数、重复块数量与强制剥离链覆盖率。每 8 个 seed 候选按这些指标排序后再进入整局 Exact Cover，第二解返回的歧义块允许通过同色相邻块之间移动一个边界格做一次局部修边，修边后仍须保持块连通和最小尺寸。
11. 唯一完整布局重新构造颜色区域并逐格比较原始 `regions`，随后由 Python 皇冠求解器验证每行、每列、每个颜色区域恰好一个皇冠且皇冠八方向不相邻。
12. 只有放置方案唯一、恢复的颜色布局与输入一致且该布局只有 1 个皇冠答案时，才能同时标记 `globalUniquePlacement=true` 和 `globalUniqueSolution=true`。
13. 从剩余方块中反复选择当前候选位置数最少的方块，形成确定性的 `solutionOrder`。

注意：`solutionOrder` 证明存在一条完整可放置路径，但当前版本没有要求每一步都只有一个候选位置；`candidateCount` 被保留用于后续调整“无猜拼块顺序”的严格程度。

## Hard 拓扑降级

当前 2000 个支持关卡中，有 384 个原棋盘只有 2 个颜色区域达到“区域至少 3 格”，无法同时满足 Hard 固定选择 3 个施工颜色的要求。

离线严格模式采用以下显式策略：

- 优先选择 3 个施工颜色；
- 原棋盘不足 3 个合法区域时选择 2 个；
- 仍使用 Hard 的 `0.8` 块数系数；
- 输出 `difficultyFallback: "hard_two_regions"`，不得静默降级。

这项策略只存在于 Python 离线生成器中，不改变当前 Godot 在线玩法。

## 抽样命令

生成一个关卡的三档数据：

```bash
python3 tools/generate_composite_levels.py \
  --level-id 71 \
  --attempts 8 \
  --max-search-nodes 100000 \
  --output /tmp/composite_level71.json
```

复查已有输出：

```bash
python3 tools/generate_composite_levels.py \
  --validate-only \
  --level-id 71 \
  --output /tmp/composite_level71.json
```

## 当前已知边界

- 放置唯一性按玩家可感知的实体形状和落点判断；同颜色、同形状、同方向的视觉相同块只交换内部 `pieceId` 时不视为第二种解。
- `solutionOrder` 证明存在一条完整可放置路径，但当前不要求路径中每一步都只有一个空间候选。
- Hard 的块数和候选原点更多；动态 MRV、状态缓存、切分质量排序和歧义块局部修边用于控制离线耗时，出现第二个符合原始颜色规则的完整方案或用尽搜索预算的候选仍会被拒绝。
- 全量生成必须保持严格失败：缺少任意“关卡 × 难度”条目时，不覆盖正式输出文件。
