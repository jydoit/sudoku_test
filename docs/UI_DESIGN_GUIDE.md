# color king UI 设计规范草案

本文档用于指导 `color king` 的 UI 视觉优化、交互状态统一和 Godot 实现落地。产品功能事实源仍为 [`docs/PRODUCT_REQUIREMENTS.md`](PRODUCT_REQUIREMENTS.md)；当本文档与产品需求冲突时，以产品需求和玩法硬约束为准。

## 1. 设计目标

`color king` 是竖屏移动端休闲逻辑谜题，视觉目标是：

- 轻松、明亮、治愈，降低逻辑谜题的压力感。
- 棋盘信息清晰，不依赖颜色也能区分区域。
- 页面层级明确：关卡页优先服务解题，首页和结果页负责情绪与入口。
- 适合碎片时间游玩，按钮足够大，反馈轻量但明确。

## 2. 页面布局基准

默认设计基准为移动端竖屏 `540 × 960`，当前 Godot 工程也使用该窗口比例。

布局原则：

- 通用页面左右安全边距：`24-32px`；关卡页为扩大正方形棋盘可收紧至单侧 `6px`，棋盘自身仍保留约 `5px` 内缩。
- 卡片内容内边距：`16-24px`。
- 模块纵向间距：`16-28px`。
- 底部主要操作按钮高度：不低于 `88px`。
- 重要点击目标最小尺寸：`48 × 48px`。
- 棋盘应优先保持正方形，并在关卡页中占据视觉中心。

关卡页建议结构：

```text
顶部轻量导航
关卡标题
棋盘主区域
底部操作区
```

关卡页顶部只保留两项与当前操作直接相关的资源信息：当前金币余额和本关红心体力。排行榜、活动、设置和广告位仍不进入关卡页。金币与红心使用并列轻量标签展示，不增加购买加号或主动促销入口；只有玩家主动使用付费道具且金币不足时才展示获取方式。

## 3. 颜色系统

### 3.1 品牌与页面颜色

建议使用语义化颜色 token 管理 UI：

| Token | 用途 | 建议值 |
| --- | --- | --- |
| `ink` | 主文字、小狮子国王轮廓 | `#26334A` |
| `muted` | 次级文字 | `#718096` |
| `surface_cream` | 关卡页背景 | `#FFF8ED` |
| `surface_card` | 卡片背景 | `#FFFFFF` |
| `primary_blue` | 首页/结果页主色 | `#3E8DFF` |
| `soft_blue` | 蓝色弱背景 | `#E7F1FF` |
| `success_green` | 提示、正向按钮 | `#48B985` |
| `warning_yellow` | 新手教程提示卡片 | `#FFF1BD` |
| `danger_red` | 错误、红心 | `#F25D72` |
| `board_border` | 棋盘外框/区域边界 | `#1F2530`，建议 alpha `0.40-0.55` |
| `assembly_tray` | 复合拼块阶段底部托盘 | `#20283A` |
| `assembly_tray_edge` | 托盘外框与深层阴影 | `#111827` |
| `assembly_well` | 尚未填充的施工区凹槽 | `#D8D5D0` |

运行时绘制边界时，将 `board_border` 预先合成到浅色页面背景，当前结果色为不透明 `#989BA0`。这样外框和区域分界不会因为底下是红色、蓝色或教程蒙层而产生不同的视觉透明度。

### 3.2 棋盘默认色板

棋盘区域色必须沿用产品文档固化的“明亮经典”10 色：

| 序号 | 颜色名 | Hex |
| --- | --- | --- |
| 1 | 红色 | `#E53935` |
| 2 | 蓝色 | `#1E88E5` |
| 3 | 绿色 | `#43A047` |
| 4 | 黄色 | `#FDD835` |
| 5 | 紫色 | `#8E24AA` |
| 6 | 青色 | `#00ACC1` |
| 7 | 橙色 | `#FB8C00` |
| 8 | 靛蓝色 | `#3949AB` |
| 9 | 黄绿色 | `#7CB342` |
| 10 | 粉色 | `#D81B60` |

规则：

- 相邻区域不能使用相近颜色。
- 不同颜色区域之间必须有非颜色维度的边界区分。
- 同一区域内部缝隙可以使用该色加深色。
- 不同区域分界和棋盘最外缘使用 `board_border`。
- 复合拼块阶段的方块顶面继续使用原区域色，不另建一套暗色方块色板；立体感只通过亮面、侧面和阴影生成，避免过场后产生“换色”感。

## 4. 字体与字号

当前 Godot 使用系统 fallback font。后续可引入统一字体，但 MVP 阶段先通过字号、字重和颜色建立层级。

建议字号：

| 场景 | 字号 |
| --- | --- |
| 首页主标题 `color king` | `36-44` |
| 关卡标题 | `28-32` |
| 结果页标题 | `34-40` |
| 新手教程提示正文 | `16-18` |
| 按钮文字 | `18-22` |
| 次级说明 | `13-15` |
| 棋盘符号 | 按格子尺寸比例计算 |

文字规则：

- 正式玩法文案优先使用“找到皇冠 / 找出皇冠”。
- 新手教程提示不应过小，移动端截图中需要裸眼可读。
- 禁用态文字不应低到不可读；建议 alpha 不低于 `0.45`。

## 5. 圆角与阴影

整体风格是柔和圆角，但棋盘要保持逻辑边界清晰。

建议圆角层级：

| 组件 | 圆角 |
| --- | --- |
| 页面大卡片 / 结果页卡片 | `24-32` |
| 顶部胶囊栏 | `22-28` |
| 新手教程提示卡片 | `14-18` |
| 底部按钮 | `18-22` |
| 棋盘格子 | 约格子尺寸 `6%-8%` |

阴影规则：

- 首页、结果页按钮可以使用较明显柔和阴影。
- 关卡页按钮阴影应轻，避免压过棋盘。
- 棋盘本身优先靠边界和色块层次，不使用重阴影。

## 6. 棋盘视觉规范

棋盘是关卡页最高优先级内容。

必须满足：

- 棋盘保持正方形。
- 棋盘尺寸和起点使用整数像素对齐，避免小数像素错位。
- 每个格子保持独立圆角矩形。
- 普通格子、提示蒙层和动画缩放使用同一套格子坐标。
- 棋盘不能只依赖颜色区分区域。

间隔与边界：

- 每个格子的圆角留白也属于间隔层。
- 同一区域内相邻格之间的间隔使用该区域颜色加深色。
- 不同区域边界使用半透明深色 `board_border`。
- 棋盘最外缘使用与区域边界一致的 `board_border`。
- `board_border` alpha 建议在 `0.40-0.55` 间调试，避免黑线压迫色块。

### 6.1 棋盘线条宽度规范

棋盘线条需要保证区域可识别，但不能比色块主体更抢眼。

外框宽度应与棋盘内部相邻格子的总间隙一致。当前每个格子两侧各使用一次 `cell_gap`，因此外框宽度为 `cell_gap * 2`，会随棋盘尺寸和实际 `cell_size` 自动变化。

通用约束：

- 外框宽度与内部格间距保持一致，避免外框显得偏窄或过重。
- 深色外框线外侧使用两层浅暖灰光晕：内层较亮、外层更宽且更透明；两层仅向棋盘外扩展，不得覆盖最外层色块。
- 外框宽度应使用整数像素，避免小数抗锯齿导致虚边。
- 外框使用四条整数像素实心边带一次性绘制，不按格子分段，避免半透明线段在接缝处重复叠加。
- 运行时使用 `cell_gap(cell_size) * 2` 计算，避免外框和内部间隙采用两套独立数值。
- 不同区域边界的视觉强度应不高于外框；可以使用同色同透明度，但宽度不应超过外框。
- 同一区域内部缝隙不画黑线，使用该色加深填充。
- 9x9 棋盘格子更小，应优先减弱线宽，避免棋盘变“网格化”。

运行时实现位于 `scripts/game_board.gd`：

```gdscript
func _region_border_width(cell_size: float) -> float:
	return _cell_gap(cell_size) * 2.0
```

外框和内部格间距使用同一套几何计算。
主关卡和新手教程必须调用同一个外框绘制函数；教程灰色引导蒙层只改变非目标格亮度，不改变外框颜色和宽度。

棋盘状态：

| 状态 | 视觉 |
| --- | --- |
| 空格 | 区域底色 |
| 普通 X | 半透明深色 X，可取消 |
| 普通皇冠 | 小狮子国王贴图，可调整 |
| 提示皇冠 | 锁定的小狮子国王贴图，保留柔和提示圈 |
| 开局国王 | 锁定的小狮子国王贴图，播放轻微缩放提醒 |
| 错误红 X | 红色 X，锁定，不可清除 |
| 提示范围 | 非操作格覆盖半透明灰色蒙层，不闪烁 |

### 6.2 X 标记视觉规范

普通 X 和错误 X 必须在全部 10 种区域色上清楚可见，并保持一眼可区分。

普通 X：

- 主线使用 `ink`，alpha 为 `0.78`。
- 符号半径为格子尺寸的 `18%`，线宽为格子尺寸的 `4.6%`，最小 `3px`。
- 主线下面增加低透明度白色细描边，防止深蓝、紫色等深色区域吞没符号。
- 不增加实心底圈，避免普通排除标记过度抢眼。

错误 X：

- 主线使用深错误红 `#D92F42`，保持不透明。
- 符号半径为格子尺寸的 `22%`，线宽为格子尺寸的 `6%`，最小 `4px`。
- 主线下面使用 `#FFF7F8` 浅色描边，描边比主线宽至少 `2.5px`。
- 背后增加 `danger_red`、alpha `0.22` 的柔和圆形底晕，圆半径为格子尺寸的 `32%`。
- 错误 X 必须明显强于普通 X，但不能遮挡区域底色和棋盘边界。

X 属于基础可缩放符号，当前优先使用 Godot 自绘线条。若后续主题皮肤需要纹理化图案，再使用透明 SVG/PNG 贴图；贴图应保留相同尺寸比例和语义颜色。

### 6.3 开局提示皇冠与进度规范

- 关卡标题下方始终展示皇冠图标、进度条和 `已找到 / 本关总数`。
- 有开局提示皇冠时，先显示轻量浮层，文案同时说明本关总皇冠数和赠送的提示皇冠数。
- 浮层中的皇冠依次运动到对应棋盘格，落位后才显示锁定皇冠，并同步增加进度。
- 每个皇冠落位后播放一次轻微缩放回弹；最大字号不超过格子尺寸的 `72%`。
- 缩放只改变皇冠字号，不放大格子绘制矩形，防止边缘格皇冠越过棋盘外框。
- 浮层期间拦截棋盘输入，全部皇冠落位后淡出并恢复操作。

### 6.4 复合拼块阶段棋盘规范

复合拼块关卡只用于 6x6-9x9。拼接阶段沿用同一个正方形棋盘几何，不创建尺寸不同的第二块棋盘，确保过场前后格子不会跳位。

立体区域构成：

- 顶面使用原“明亮经典”区域色。
- 顶面左上侧叠加向白色混合 `12%-18%` 的柔和高光；下侧与右侧使用向黑色混合 `18%-28%` 的侧面色。
- 视觉厚度建议为格子尺寸的 `8%-12%`，并限制在 `4-8px`；厚度不能改变方块实际占格和吸附坐标。
- 投影向下偏移 `3-6px`，模糊范围轻于首页按钮阴影。相邻同一方块的格子共用外轮廓和侧面，不在内部制造独立“巧克力格”边界。
- 已锁定区域和用户已放置方块使用相同立体材质；锁定状态通过不可拿取和稳定底座表达，不依赖降低颜色透明度。

施工区：

- 使用 `assembly_well` 中性凹槽，保留清晰格子吸附位置和整个施工区外轮廓。
- 每种施工颜色保留至少一个不可移动的原色立体格，作为颜色与连通方向线索；线索格不加箭头、虚线或目标边界。
- 多区域玩法不显示不同施工颜色之间的预设内部边界，也不使用虚线泄露正确拼法；Simple/Medium/Hard 分别允许 1-2/2/3 组凹槽分散在棋盘不同位置。
- 空槽顶面比页面背景深，内侧使用上/左深、下/右浅的反向边缘，形成“向内凹”而非可点击普通棋盘格的感觉。
- 锁定区、施工区和托盘方块必须同时具有颜色之外的高度或轮廓差异，满足色弱可识别要求。

拖动状态：

| 状态 | 视觉反馈 |
| --- | --- |
| 托盘待放 | 原色立体缩略方块，完整显示形状包围盒 |
| 拿起 | 放大到棋盘格尺寸，整体上移至手指上方，投影略增强 |
| 合法预览 | 对应施工格显示完整占格轮廓，方块保持原色且 alpha 不低于 `0.82` |
| 非法预览 | 占格轮廓使用 `danger_red`，方块轻微横向回弹；不能只用红色表达非法 |
| 已放置 | 与锁定区同高度的立体方块，可再次拿起 |
| 正在回收 | 托盘自动滚动至头部方向第一个空槽，目标槽使用蓝白轮廓并显示半透明方块预览 |

方块过场压平时，顶面颜色保持不变，侧面高度、投影和同一颜色内部的拼块切缝同步收敛；最终只保留标准二维棋盘的颜色区域边界。转换结束前不得提前绘制 X、皇冠或提示蒙层。

## 7. 按钮规范

按钮优先使用大圆角卡片。

底部操作区建议三等分：

```text
[ 清除 ] [ 皇冠直找 ] [ 提示 ]
```

三个道具按钮统一使用纵向结构：`48 × 48px` 图标在上，`15-17px` 道具名称、剩余次数或金币价格在下。按钮高度不低于 `88px`，三项等宽；清除固定显示“免费”，皇冠直找和提示在免费次数耗尽后显示金币价格。

按钮状态：

| 状态 | 视觉 |
| --- | --- |
| 默认 | 白色或浅色卡片 + 清晰图标文字 |
| 强操作 | 品牌色或浅绿色强调 |
| 禁用 | 保留轮廓和可读文字，降低饱和度，不完全“消失” |
| 按下 | 轻微缩放或颜色加深 |

交互反馈：

- 点击按钮：轻微缩放。
- 使用提示：按钮可短暂亮起。
- 次数不足：不强打断，展示弹窗或 toast 占位。

## 8. 首页规范

首页目标是建立品牌感和进入当前关卡。

首页应包含：

- `color king` 主标题。
- 柔和蓝色主视觉。
- “开始关卡”主按钮。
- “拼块玩法”次主按钮，使用区别于主线蓝色的紫色，但保持同一圆角、阴影和点击尺寸；完成新人流程后可用，进入独立 6x6 拼块挑战。
- “新人流程”入口用于重新体验新手教程；老玩家进入前保存正式关卡现场，完成或跳过后返回原关卡，新用户才进入第 1 关。

三个入口按“开始关卡 / 拼块玩法 / 新人流程”纵向排列。“开始关卡”高度和视觉权重最高；拼块玩法居中承接新玩法发现；新人流程使用白色弱按钮。拼块体验返回首页时必须先恢复进入前的主线棋盘与资源，再刷新首页文案。

首页不显示：

- 金币、红心、星数。
- 排行榜、活动、宝箱。
- 底部导航。

## 9. 关卡页规范

关卡页目标是让玩家专注解题。

必须显示：

- 返回首页按钮。
- 当前持有金币。
- 本关独立红心体力槽。
- 设置入口。
- 选关入口。
- 当前关卡标题。
- 棋盘。
- 清除、皇冠直找、提示按钮。

不应显示：

- 金币购买加号或促销横幅。
- 设置入口。
- 广告位。
- 排行榜/社交入口。

当前截图中的优先优化方向：

- 正式关卡移除黄色教练提示卡，将释放的纵向空间主要交给棋盘。
- 正式关卡提示道具仅通过棋盘蒙层、正常亮度格和可操作范围体现，不显示解释文字；提示范围只包含可单击画 X 的非皇冠空格。
- 提示蒙层使用 `70%` 冷灰色覆盖整个棋盘，包括格间接缝和区域边界；随后重绘提示相关格和已有标记，避免逐格圆角蒙层产生接缝错位。
- 区域边界在提示状态下统一变暗但不隐藏；正式关卡中全部保持明亮的提示目标格都可单击画 X，并播放一次柔和光环，不使用实线框或持续闪烁。
- 底部禁用按钮需要更像“暂不可用”，而不是“坏掉/丢失”。
- 棋盘边界应轻于色块主体，避免黑线抢视觉。

### 9.1 新手教程布局

新手教程使用与正式关卡相同的页面骨架，不单独维护一套精简布局：

- 顶部保留首页、金币、红心和帮助入口，并用“跳过”替代“选关”。
- 正常显示“新手教程”标题、皇冠进度、教练提示卡和正方形棋盘。
- 底部保持清除、皇冠直找、提示三等分布局，避免玩家进入正式关卡后重新识别工具位置。
- 强引导阶段不需要的道具保持可见但使用禁用态；提示和皇冠直找在对应教学阶段使用黄色强调，并由小手指向。
- 教程中的皇冠直找生成与正式道具相同的锁定提示皇冠，但不扣除免费次数或金币；直找后根据棋盘现状继续引导尚未完成的规则排除。

### 9.2 复合拼块关卡布局

拼接阶段使用以下竖屏结构：

```text
┌────────────────────────────┐
│ 首页  金币  红心  Help 设置       │
│ 拼块挑战 · 第 N 局 · 先拼好颜色区域 │
│                            │
│       6x6-9x9 立体棋盘       │
│                            │
├────────────────────────────┤
│  ‹  彩色方块  彩色方块  …  ›   │
│       深色横向滑动托盘          │
└────────────────────────────┘
```

- 顶部导航与普通关卡保持位置稳定；独立拼块入口隐藏“选关”，标题使用“拼块挑战 · 第 N 局”，避免显示伪造的主线关卡号；皇冠进度在拼接阶段隐藏，并由简短阶段标识占据对应信息层级。
- 棋盘仍优先保持最大可用正方形。6x6 为最小尺寸，不得为了托盘把棋盘压缩到难以看清单格的位置。
- 底部原三个道具的整体区域替换为托盘，托盘建议高度 `168-220px`，并包含设备底部安全区。
- 托盘使用单行水平滚动，不把所有方块压缩到同一屏；左右边缘使用轻微渐隐或半露方块提示还有内容，不持续播放箭头动画。
- 每个托盘槽按方块包围盒自适应宽度，建议 `96-180px`；预览缩放保持所有格子可辨认，不能裁掉长条或 L 形转角。
- 拖动方块时托盘槽位数量和宽度保持不变，不因少一块引起整体跳动；从棋盘回收时使用从头部找到的第一个空槽，回收后的槽位占用需要随现场存档。
- 独立挑战完成后主按钮显示“下一局”，立即更换基础 6x6 盘与随机种子；次按钮返回首页并恢复主线现场。

手势仲裁：

- 在托盘空白处或方块上以水平移动为主时滚动托盘。
- 在方块上明显向上移动并越过拿取阈值时进入拖放；进入拖放后停止托盘滚动，直到放置或回收完成。
- 拿起方块的显示中心位于触点上方约 `0.7-1.0` 个棋盘格，确保手指不遮挡占格预览。
- 方块始终显示在手指上方，拖动视觉与格子换算共用同一锚点；约 `0.95` 格范围内优先磁吸到最近合法凹槽。放到合法位置时使用 `0.10-0.18s` 的吸附落位；非法释放使用 `0.18-0.28s` 回到原位置，不留下半格状态。
- 棋盘中的已放方块可再次向下拖动；进入托盘回收热区时自动寻找头部方向第一个空槽，将横滑视口平滑对焦到该槽并显示方块缩略预览；在热区内释放后归位，移出热区则取消预览。
- 锁定颜色区域不响应长按、拖动或点击缩放，避免误导用户认为可以移动。

首次流程动画：

- 第一次进入任意复合拼块关卡时，在真实页面骨架上播放 `6-9s` 的影子手演示。
- 顺序为：指示锁定区 → 指示施工区 → 横向滑动托盘 → 向上拖出方块 → 合法吸附 → 从棋盘拖回托盘 → 快速预览完整拼接与二维转换。
- 演示操作使用副本，结束后恢复真实初始状态；过程中不扣道具、金币或红心。
- 后续关卡不自动播放。Help 的“拼块玩法”页提供分步图示与“重播演示”，重播结束后返回进入 Help 前的真实状态。

Help 结构：

```text
[消除规则] [拼块玩法]

拼块玩法：
1. 从深色托盘向上拖出彩色方块
2. 左右滑动托盘查看更多方块
3. 方块必须完整对齐凹槽，同色最终保持连续
4. 已放方块可以拖回托盘
5. 拼完整盘后自动进入找皇冠

[重播演示]
```

- 拼接阶段打开 Help 默认选中“拼块玩法”；皇冠阶段默认选中“消除规则”。
- Help 内的动图或示意图必须包含立体锁定区、凹槽、深色托盘和回收动作，不能只用文字说明。
- 所有标题、步骤和按钮纳入现有五语言翻译；RTL 只镜像 Help 与托盘滚动布局，不镜像棋盘坐标或方块局部形状。

### 9.3 多语言与 RTL

- 顶部设置使用与帮助按钮一致的 `46 x 46px` 点击目标，齿轮图标不依赖语言。
- 语言设置使用统一模态弹窗，选项以语言自身名称展示：English、中文、العربية、Français、Latina。
- 默认语言来自设备系统 locale；用户主动选择后由存档覆盖系统默认值。
- 所有静态控件通过 `LocalizationController` 注册到 Godot 翻译服务，动态数字文案调用控制器先翻译模板再格式化。
- 阿拉伯语将根界面方向切换为 RTL，顶部导航、弹窗和按钮顺序随继承方向镜像；棋盘坐标和关卡逻辑不镜像。
- 字体栈以 Noto Sans SC 为主字体、Noto Sans Arabic 为 fallback，打包产物必须同时包含两份字体和 OFL 许可证。
- 英语、中文、法语和拉丁语使用 LTR，不允许保留上一次阿拉伯语的布局方向。

## 10. 结果页规范

结果页使用蓝色主色系整屏结构。

成功页：

```text
顶部：完成文案
中部：皇冠展位 / 奖励视觉
底部：[下一关] [主菜单]
```

失败页：

```text
顶部：挑战失败
中部：红心/失败反馈
底部：[金币复活] [重新挑战]
```

结果页不显示排行榜、广告、复杂奖励进度。

金币复活按钮必须直接展示本次价格。复活后保留棋盘并恢复 1 颗红心；金币不足时使用系统弹窗展示“观看激励广告 / 购买金币 / 稍后再说”，不得自动播放广告。

拼块死局沿用同一结果页骨架，标题改为“拼块死局”，反馈说明同色区域已被隔离；底部按钮为“金币复活 -N”和“重新开始本局”。拼块复活不处理红心，而是自动将最后一次放置或移动的方块退回托盘，并解除棋盘输入锁定。

### 10.1 金币与付费提示视觉

- 顶部金币标签只显示图标和余额，不使用闪烁、红点或强促销动画。
- 顶部红心与金币标签同高；每颗红心保留至少 `32 × 38px` 独立空间，不允许通过压缩间距或字号适配。
- 有效红心使用红色实心图案，循环播放两次轻微心跳后停顿；失去的红心立即恢复 `1.0` 比例、变为灰色实心图案并停止动画。
- 金币图标使用 `assets/ui/coin.png` 的透明 PNG 贴图，显示尺寸为 `28 × 28px`；不得退化为圆点字符或货币符号。
- 免费次数存在时，道具按钮显示 `×剩余次数`；免费次数耗尽后改为 `-金币价格`。
- 所有价格必须在点击前可见，扣款后余额立即刷新。
- 金币不足弹窗需要同时展示价格、当前余额和缺口。
- 激励广告按钮同时展示预计补币数量，且一次补币足以完成当前请求。
- 激励广告是玩家主动选择，不在开局、解题中途或通关后自动弹出。
- 当前购买与激励广告为接入占位；视觉上不得暗示已经到账。

## 11. 动效规范

动效目标是“轻快确认”，不是强刺激。

建议：

- 格子点击：`0.08-0.14s` 轻微缩放。
- 皇冠出现：`0.25-0.5s` 弹性缩放。
- 开局国王提示：轻微放大-回弹，不加金色光晕。
- 错误反馈：轻微震动或短闪，不长时间干扰。
- 通关反馈：棋盘轻闪 + 皇冠弹跳 + 结果页淡入。
- 有效红心：`1.0 → 1.13 → 1.0 → 1.08 → 1.0` 后停顿；单颗失效后只停止该颗动画，剩余红心继续跳动。
- 拼块合法吸附：`0.10-0.18s` 下落并轻微回弹；非法释放：`0.18-0.28s` 回到原槽位。
- 拼块完成转换：总时长 `0.8-1.4s`，依次完成落位确认、立体厚度收敛、内部拼块缝隙合并、托盘退出和皇冠 UI 淡入；转换期间拦截全部输入。

避免：

- 高频闪烁。
- 大面积强红警告。
- 长时间遮挡棋盘。

## 11.1 统一弹窗规范

所有模态弹窗使用游戏内绘制的全屏遮罩和圆角卡片，不直接依赖
`AcceptDialog`、`ConfirmationDialog` 等系统窗口外观。这样可以确保编辑器、桌面导出和移动端导出的标题栏、背景、边框与按钮保持一致。

弹窗基础视觉 token：

| Token | 用途 | 值 |
| --- | --- | --- |
| `dialog_scrim` | 全屏遮罩 | `#1A2438`，alpha `0.38` |
| `dialog_surface` | 弹窗背景 | `#FFFDF8` |
| `dialog_border` | 弹窗边框 | `#E7DED1` |
| `dialog_content_surface` | 富内容区块背景 | `#F7FAFF` |
| `dialog_content_border` | 富内容区块边框 | `#DFEAF6` |

弹窗卡片统一使用 `24px` 圆角、`2px` 边框，以及 alpha `0.16`、尺寸
`12px`、向下偏移 `5px` 的柔和阴影。内容左右内边距为 `24px`，上下内边距为
`20px`，区块间距为 `16px`。标准弹窗宽度为 `420px`，包含图片或复杂控件的富内容弹窗宽度为
`460px`；实际宽度不得超过视口宽度减 `48px`，高度不得超过视口高度的 `82%`。

标题和正文层级：

- 标题使用 `22px`、`ink`，左对齐。
- 主要正文使用 `16px`、`ink`。
- 次级说明使用 `14px`、`muted`。
- 信息类和帮助类弹窗可以显示右上角关闭按钮，点击区域不小于 `44 x 44px`。
- 需要用户明确选择的重要确认弹窗不依赖点击遮罩关闭。

按钮高度统一为 `48px`、圆角 `14px`、间距 `12px`。主按钮使用
`primary_blue` 和白色文字，次按钮使用 `#F1F4F7` 和 `ink`，不可逆操作才使用
`danger_red`。取消或次要操作在左，确认或主操作在右；三个操作时保持等宽，主操作仍位于最右侧。

交互与动效：

- 打开时遮罩淡入，卡片在 `0.18s` 内从 `0.96` 缩放到 `1.0`。
- 关闭时在 `0.14s` 内淡出。
- 遮罩拦截底层输入，点击弹窗外部默认不关闭。
- `Esc` 和移动端返回键执行取消或关闭。
- 打开后主操作按钮获得焦点。
- 同一时间只显示一个模态弹窗，新弹窗打开前收起旧弹窗。

弹窗统一支持信息、确认、多操作和自定义内容四种模式。帮助规则、关卡选择、跳过教程、恢复教程和金币不足提示都使用
`scripts/dialog_controller.gd`；toast 和教程中央提示属于非模态反馈，不纳入弹窗控制器。

### 12.1 规范如何落地到代码

`UI_DESIGN_GUIDE.md` 本身不会自动影响游戏运行，它的作用是把设计决策稳定下来。真正生效需要经过四层：

1. 文档层：在本文档中确定视觉规范。
2. Token 层：把共享规范同步到 `scripts/ui_tokens.gd`。
3. 代码层：页面和棋盘只引用 token 常量、样式函数或绘制参数。
4. 验收层：通过截图、真机测试和 smoke test 确认实现符合规范。

落地优先级：

```text
PRODUCT_REQUIREMENTS.md 约束玩法和产品事实
UI_DESIGN_GUIDE.md 约束视觉和交互表现
scripts/*.gd 决定运行时真实效果
tests/*.gd 保障关键行为不回退
```

- 先在本文档确定 token 或尺寸范围。
- 再改对应 GDScript 常量/函数。
- UI 改动完成后同步 `PRODUCT_REQUIREMENTS.md` 中相关实现说明。
- 最后运行 `smoke_test.gd` 和 `tutorial_smoke_test.gd`。

建议后续重构方向：

- 新增共享视觉参数时，先加入 `scripts/ui_tokens.gd`，避免页面脚本各自维护相同数值。
- 将按钮样式函数统一命名和参数化。
- 将棋盘视觉参数集中到 `GameBoard` 顶部常量。
- UI 改动后同步更新 `PRODUCT_REQUIREMENTS.md` 和本文档。

## 13. UI 回归检查清单

每次 UI 改动后至少检查：

- 540 × 960 下没有裁切和遮挡。
- 关卡页主要按钮高度不低于 `48px`。
- 正式关卡无教练提示文字区，新手教程提示文案可读。
- 棋盘保持正方形且无像素错位。
- 色块边界可辨认，色弱用户不只依赖颜色。
- 普通 X、皇冠、提示皇冠、开局国王、错误红 X 均可区分。
- 检查 6x6-9x9 棋盘在复合拼接阶段不会被托盘压缩或遮挡；立体方块颜色与转换后的二维区域一致。
- 检查复合拼块的托盘横向滚动、向上拿取、合法/非法占格预览、已放方块回收、首次演示与 Help 重播均可在单指触控下完成。
- 检查复合拼接阶段不出现皇冠进度和三个道具，转换完成后它们恢复且布局不跳动。
- 首页、关卡页、结果页职责没有混淆。
- smoke test 和 tutorial smoke test 通过。
