# color king UI 设计规范草案

本文档用于指导 `color king` 的 UI 视觉优化、交互状态统一和 Godot 实现落地。产品功能事实源仍为 [`docs/PRODUCT_REQUIREMENTS.md`](PRODUCT_REQUIREMENTS.md)；当本文档与产品需求冲突时，以产品需求和玩法硬约束为准。

## 1. 设计目标

`color king` 是竖屏移动端休闲逻辑谜题，视觉目标是：

- 轻松、明亮、治愈，降低逻辑谜题的压力感。
- 棋盘信息清晰，不依赖颜色也能区分区域。
- 页面层级明确：关卡页优先服务解题，首页和结果页负责情绪与入口。
- 适合碎片时间游玩，按钮足够大，反馈轻量但明确。

## 2. 页面布局基准

默认设计基准为移动端竖屏 `540 × 960`，当前 Godot 工程也使用该窗口比例。

布局原则：

- 页面左右安全边距：`24-32px`。
- 卡片内容内边距：`16-24px`。
- 模块纵向间距：`16-28px`。
- 底部主要操作按钮高度：不低于 `64px`。
- 重要点击目标最小尺寸：`48 × 48px`。
- 棋盘应优先保持正方形，并在关卡页中占据视觉中心。

关卡页建议结构：

```text
顶部轻量导航
关卡标题
教练提示卡片
棋盘主区域
底部操作区
```

关卡页不承载金币、排行榜、活动、设置、广告等干扰元素。

## 3. 颜色系统

### 3.1 品牌与页面颜色

建议使用语义化颜色 token 管理 UI：

| Token | 用途 | 建议值 |
| --- | --- | --- |
| `ink` | 主文字、皇冠图标 | `#26334A` |
| `muted` | 次级文字 | `#718096` |
| `surface_cream` | 关卡页背景 | `#FFF8ED` |
| `surface_card` | 卡片背景 | `#FFFFFF` |
| `primary_blue` | 首页/结果页主色 | `#3E8DFF` |
| `soft_blue` | 蓝色弱背景 | `#E7F1FF` |
| `success_green` | 提示、正向按钮 | `#48B985` |
| `warning_yellow` | 教练提示卡片 | `#FFF1BD` |
| `danger_red` | 错误、红心 | `#F25D72` |
| `board_border` | 棋盘外框/区域边界 | `#1F2530`，建议 alpha `0.40-0.55` |

### 3.2 棋盘默认色板

棋盘区域色必须沿用产品文档固化的“明亮经典”10 色：

| 序号 | 颜色名 | Hex |
| --- | --- | --- |
| 1 | 红色 | `#E53935` |
| 2 | 蓝色 | `#1E88E5` |
| 3 | 绿色 | `#43A047` |
| 4 | 黄色 | `#FDD835` |
| 5 | 紫色 | `#8E24AA` |
| 6 | 青色 | `#00ACC1` |
| 7 | 橙色 | `#FB8C00` |
| 8 | 靛蓝色 | `#3949AB` |
| 9 | 黄绿色 | `#7CB342` |
| 10 | 粉色 | `#D81B60` |

规则：

- 相邻区域不能使用相近颜色。
- 不同颜色区域之间必须有非颜色维度的边界区分。
- 同一区域内部缝隙可以使用该色加深色。
- 不同区域分界和棋盘最外缘使用 `board_border`。

## 4. 字体与字号

当前 Godot 使用系统 fallback font。后续可引入统一字体，但 MVP 阶段先通过字号、字重和颜色建立层级。

建议字号：

| 场景 | 字号 |
| --- | --- |
| 首页主标题 `color king` | `36-44` |
| 关卡标题 | `28-32` |
| 结果页标题 | `34-40` |
| 教练提示正文 | `16-18` |
| 按钮文字 | `18-22` |
| 次级说明 | `13-15` |
| 棋盘符号 | 按格子尺寸比例计算 |

文字规则：

- 正式玩法文案优先使用“找到皇冠 / 找出皇冠”。
- 教练提示不应过小，移动端截图中需要裸眼可读。
- 禁用态文字不应低到不可读；建议 alpha 不低于 `0.45`。

## 5. 圆角与阴影

整体风格是柔和圆角，但棋盘要保持逻辑边界清晰。

建议圆角层级：

| 组件 | 圆角 |
| --- | --- |
| 页面大卡片 / 结果页卡片 | `24-32` |
| 顶部胶囊栏 | `22-28` |
| 教练提示卡片 | `14-18` |
| 底部按钮 | `18-22` |
| 棋盘格子 | 约格子尺寸 `6%-8%` |

阴影规则：

- 首页、结果页按钮可以使用较明显柔和阴影。
- 关卡页按钮阴影应轻，避免压过棋盘。
- 棋盘本身优先靠边界和色块层次，不使用重阴影。

## 6. 棋盘视觉规范

棋盘是关卡页最高优先级内容。

必须满足：

- 棋盘保持正方形。
- 棋盘尺寸和起点使用整数像素对齐，避免小数像素错位。
- 每个格子保持独立圆角矩形。
- 普通格子、提示蒙层和动画缩放使用同一套格子坐标。
- 棋盘不能只依赖颜色区分区域。

间隔与边界：

- 每个格子的圆角留白也属于间隔层。
- 同一区域内相邻格之间的间隔使用该区域颜色加深色。
- 不同区域边界使用半透明深色 `board_border`。
- 棋盘最外缘使用与区域边界一致的 `board_border`。
- `board_border` alpha 建议在 `0.40-0.55` 间调试，避免黑线压迫色块。

### 6.1 棋盘线条宽度规范

棋盘线条需要保证区域可识别，但不能比色块主体更抢眼。

外框宽度建议：

| 棋盘尺寸 | 外框宽度 |
| --- | --- |
| 5x5 | `4px` |
| 6x6 | `4px` |
| 7x7 | `3px` |
| 8x8 | `3px` |
| 9x9 | `2px` |

通用约束：

- 外框最小 `2px`，最大 `4px`。
- 外框宽度应使用整数像素，避免小数抗锯齿导致虚边。
- 如果自动按格子尺寸计算，建议使用 `cell_size * 0.04`，再 clamp 到 `2-4px`。
- 不同区域边界的视觉强度应不高于外框；可以使用同色同透明度，但宽度不应超过外框。
- 同一区域内部缝隙不画黑线，使用该色加深填充。
- 9x9 棋盘格子更小，应优先减弱线宽，避免棋盘变“网格化”。

当前实现可以映射为：

```gdscript
const REGION_BORDER_COLOR := Color("#1F2530", 0.46)

func _region_border_width(cell_size: float) -> float:
	var width := maxi(2, int(round(cell_size * 0.040)))
	return float(width if width % 2 == 0 else width + 1)
```

后续如果要严格按棋盘尺寸控制，可改为按 `rows/cols` 分档返回 `2-4px`。

棋盘状态：

| 状态 | 视觉 |
| --- | --- |
| 空格 | 区域底色 |
| 普通 X | 半透明深色 X，可取消 |
| 普通皇冠 | `ink` 色皇冠，可调整 |
| 提示皇冠 | 锁定皇冠，后续可加柔和提示圈 |
| 开局国王 | 锁定皇冠，播放轻微缩放提醒 |
| 错误红 X | 红色 X，锁定，不可清除 |
| 提示范围 | 非操作格覆盖半透明灰色蒙层，不闪烁 |

## 7. 按钮规范

按钮优先使用大圆角卡片。

底部操作区建议三等分：

```text
[ 红心/生命 ] [ 皇冠直找 ] [ 提示 ]
```

按钮状态：

| 状态 | 视觉 |
| --- | --- |
| 默认 | 白色或浅色卡片 + 清晰图标文字 |
| 强操作 | 品牌色或浅绿色强调 |
| 禁用 | 保留轮廓和可读文字，降低饱和度，不完全“消失” |
| 按下 | 轻微缩放或颜色加深 |

交互反馈：

- 点击按钮：轻微缩放。
- 使用提示：按钮可短暂亮起。
- 次数不足：不强打断，展示弹窗或 toast 占位。

## 8. 首页规范

首页目标是建立品牌感和进入当前关卡。

首页应包含：

- `color king` 主标题。
- 柔和蓝色主视觉。
- “开始关卡”主按钮。
- “新人流程”入口，用于调试/验收。

首页不显示：

- 金币、红心、星数。
- 排行榜、活动、宝箱。
- 底部导航。

## 9. 关卡页规范

关卡页目标是让玩家专注解题。

必须显示：

- 返回首页按钮。
- 选关入口。
- 当前关卡标题。
- 教练提示卡片。
- 棋盘。
- 红心、皇冠直找、提示按钮。

不应显示：

- 金币栏。
- 设置入口。
- 广告位。
- 排行榜/社交入口。

当前截图中的优先优化方向：

- 教练提示卡片文字需要更清晰。
- 棋盘与提示卡之间应建立稳定间距。
- 底部禁用按钮需要更像“暂不可用”，而不是“坏掉/丢失”。
- 棋盘边界应轻于色块主体，避免黑线抢视觉。

## 10. 结果页规范

结果页使用蓝色主色系整屏结构。

成功页：

```text
顶部：完成文案
中部：皇冠展位 / 奖励视觉
底部：[下一关] [主菜单]
```

失败页：

```text
顶部：挑战失败
中部：红心/失败反馈
底部：[重新挑战] [返回首页]
```

结果页不显示排行榜、广告、复杂奖励进度。

## 11. 动效规范

动效目标是“轻快确认”，不是强刺激。

建议：

- 格子点击：`0.08-0.14s` 轻微缩放。
- 皇冠出现：`0.25-0.5s` 弹性缩放。
- 开局国王提示：轻微放大-回弹，不加金色光晕。
- 错误反馈：轻微震动或短闪，不长时间干扰。
- 通关反馈：棋盘轻闪 + 皇冠弹跳 + 结果页淡入。

避免：

- 高频闪烁。
- 大面积强红警告。
- 长时间遮挡棋盘。

### 12.1 规范如何落地到代码

`UI_DESIGN_GUIDE.md` 本身不会自动影响游戏运行，它的作用是把设计决策稳定下来。真正生效需要经过三层：

1. 文档层：在本文档中确定视觉规范。
2. 代码层：把规范转成 Godot 常量、样式函数或绘制函数。
3. 验收层：通过截图、真机测试和 smoke test 确认实现符合规范。

落地优先级：

```text
PRODUCT_REQUIREMENTS.md 约束玩法和产品事实
UI_DESIGN_GUIDE.md 约束视觉和交互表现
scripts/*.gd 决定运行时真实效果
tests/*.gd 保障关键行为不回退
```

当前可直接映射的代码点：

| 规范项 | 当前代码位置 | 说明 |
| --- | --- | --- |
| 棋盘区域色板 | `scripts/main.gd` 的 `REGION_COLORS` | 固定“明亮经典”色板 |
| 主文字色 | `scripts/main.gd` 的 `INK`、`scripts/game_board.gd` 的 `BOARD_INK` | 后续可统一成同一 token |
| 棋盘边界色 | `scripts/game_board.gd` 的 `REGION_BORDER_COLOR` | 控制外框和区域分界色 |
| 同区域缝隙深浅 | `scripts/game_board.gd` 的 `SAME_REGION_GAP_MIX` | 控制同色内部间隔 |
| 棋盘格子尺寸 | `scripts/game_board.gd` 的 `_board_geometry()` | 负责正方形和整数像素对齐 |
| 格子间隔 | `scripts/game_board.gd` 的 `_cell_gap()` | 控制圆角格之间的间隔 |
| 格子圆角 | `scripts/game_board.gd` 的 `_cell_corner_radius()` | 控制独立格子圆角 |
| 外框线宽 | `scripts/game_board.gd` 的 `_region_border_width()` | 控制棋盘外框宽度 |
| 按钮样式 | `scripts/main.gd` 的 `_button_style()`、`_card_style()` 等 | 后续应收敛成统一按钮 token |

开发流程建议：

- 先在本文档确定 token 或尺寸范围。
- 再改对应 GDScript 常量/函数。
- UI 改动完成后同步 `PRODUCT_REQUIREMENTS.md` 中相关实现说明。
- 最后运行 `smoke_test.gd` 和 `tutorial_smoke_test.gd`。

建议后续重构方向：

- 将颜色 token 抽到统一常量区。
- 将按钮样式函数统一命名和参数化。
- 将棋盘视觉参数集中到 `GameBoard` 顶部常量。
- UI 改动后同步更新 `PRODUCT_REQUIREMENTS.md` 和本文档。

## 13. UI 回归检查清单

每次 UI 改动后至少检查：

- 540 × 960 下没有裁切和遮挡。
- 关卡页主要按钮高度不低于 `48px`。
- 教练提示文案可读。
- 棋盘保持正方形且无像素错位。
- 色块边界可辨认，色弱用户不只依赖颜色。
- 普通 X、皇冠、提示皇冠、开局国王、错误红 X 均可区分。
- 首页、关卡页、结果页职责没有混淆。
- smoke test 和 tutorial smoke test 通过。
