# color king UI 设计规范草案

本文档用于指导 `color king` 的 UI 视觉优化、交互状态统一和 Godot 实现落地。产品功能事实源仍为 [`docs/PRODUCT_REQUIREMENTS.md`](PRODUCT_REQUIREMENTS.md)；当本文档与产品需求冲突时，以产品需求和玩法硬约束为准。

## 1. 设计目标

`color king` 是竖屏移动端休闲逻辑谜题，视觉目标是：

- 轻松、明亮、治愈，降低逻辑谜题的压力感。
- 棋盘信息清晰，不依赖颜色也能区分区域。
- 页面层级明确：关卡页优先服务解题，首页和结果页负责情绪与入口。
- 适合碎片时间游玩，按钮足够大，反馈轻量但明确。

## 2. 页面布局基准

默认设计基准为移动端竖屏 `540 × 960`，当前 Godot 工程也使用该窗口比例。

布局原则：

- 通用页面左右安全边距：`24-32px`；关卡页为扩大正方形棋盘可收紧至单侧 `6px`，棋盘自身仍保留约 `5px` 内缩。
- 卡片内容内边距：`16-24px`。
- 模块纵向间距：`16-28px`。
- 底部主要操作按钮高度：不低于 `88px`。
- 重要点击目标最小尺寸：`48 × 48px`。
- 棋盘应优先保持正方形，并在关卡页中占据视觉中心。

关卡页建议结构：

```text
顶部轻量导航
关卡标题
棋盘主区域
底部操作区
```

关卡页顶部只保留与当前操作直接相关的信息和入口：返回首页、当前金币余额、本关红心体力、帮助、设置和选关。排行榜、活动、宝箱、社交入口和广告位不进入关卡页。金币与红心使用并列轻量标签展示，不增加购买加号或主动促销入口；只有玩家主动使用付费道具且金币不足时才展示获取方式。

## 3. 颜色系统

### 3.1 品牌与页面颜色

建议使用语义化颜色 token 管理 UI：

| Token | 用途 | 建议值 |
| --- | --- | --- |
| `ink` | 主文字、小狮子国王轮廓 | `#26334A` |
| `muted` | 次级文字 | `#718096` |
| `surface_cream` | 关卡页背景 | `#FFF8ED` |
| `surface_card` | 卡片背景 | `#FFFFFF` |
| `primary_blue` | 首页/结果页主色 | `#3E8DFF` |
| `soft_blue` | 蓝色弱背景 | `#E7F1FF` |
| `success_green` | 提示、正向按钮 | `#48B985` |
| `warning_yellow` | 新手教程提示卡片 | `#FFF1BD` |
| `danger_red` | 错误、红心 | `#F25D72` |
| `board_border` | 历史棋盘外框色 | 当前棋盘不绘制深色外框，保留 token 供旧示意或调试参考 |

运行时绘制边界时，棋盘最外缘不再使用深色外框。不同颜色区域之间不画深色线，统一露出白色棋盘底板形成的格间距，并结合圆角色块和更明显的底纹图案区分区域，确保每个格子仍是独立圆角矩形，不能合并成整块色块。

### 3.2 棋盘默认色板

棋盘区域色必须沿用产品文档固化的“明亮经典”10 色：

| 序号 | 颜色名 | Hex | 底纹 |
| --- | --- | --- | --- |
| 1 | 蓝色 | `#38A7F4` | 散点纹 |
| 2 | 红色 | `#FB5958` | 三竖线纹 |
| 3 | 绿色 | `#4FC267` | 爪印点纹 |
| 4 | 金色 | `#FFDD45` | 双弧纹 |
| 5 | 紫色 | `#AA30C4` | 菱形点阵 |
| 6 | 橙色 | `#FF9A3D` | 斜线纹 |
| 7 | 青色 | `#35D6D0` | 圆环纹 |
| 8 | 粉色 | `#FF7BC8` | 双横线纹 |
| 9 | 青柠色 | `#A7DE38` | 弧叶纹 |
| 10 | 靛蓝色 | `#5F7CFF` | 菱形纹 |

规则：

- 相邻区域不能使用相近颜色。
- 不同颜色区域之间必须有非颜色维度的区分，但不使用深色分割线；优先依靠白色格间距、独立圆角和底纹图案。
- 每个颜色必须绑定一个固定底纹，颜色说明和实现文档中同时展示色值与底纹名称，避免只用颜色传达区域。
- 区域底纹使用 `REGION_PATTERN_ALPHA = 0.30`、`REGION_PATTERN_DARKEN = 0.20`，应比旧版更容易看见，但不得压过普通 X、小狮子或错误红 X。
- 区域底纹不得使用交叉线或任何近似 X 的图形，避免与普通排除 X、错误红 X 混淆。
- 同一区域内部不画黑线或深色线；间隔露出白色棋盘底板，视觉上没有区域边框，但每个格子仍清楚独立。
- `board_border` 当前不用于棋盘运行时绘制，也不用于不同颜色区域之间。

## 4. 字体与字号

当前 Godot 使用随包发布的 Noto Sans SC 作为主字体，并注册 Noto Sans Arabic 作为阿拉伯语 fallback。字号、字重和颜色仍负责建立主要层级。

建议字号：

| 场景 | 字号 |
| --- | --- |
| 首页主标题 `color king` | `36-44` |
| 关卡标题 | `28-32` |
| 结果页标题 | `34-40` |
| 新手教程提示正文 | `16-18` |
| 按钮文字 | `18-22` |
| 次级说明 | `13-15` |
| 棋盘符号 | 按格子尺寸比例计算 |

文字规则：

- 正式玩法文案优先使用“找到小狮子 / 找出小狮子”。
- 新手教程提示不应过小，移动端截图中需要裸眼可读。
- 禁用态文字不应低到不可读；建议 alpha 不低于 `0.45`。

## 5. 圆角与阴影

整体风格是柔和圆角，但棋盘要保持逻辑边界清晰。

建议圆角层级：

| 组件 | 圆角 |
| --- | --- |
| 页面大卡片 / 结果页卡片 | `24-32` |
| 顶部胶囊栏 | `22-28` |
| 新手教程提示卡片 | `14-18` |
| 底部按钮 | `18-22` |
| 棋盘格子 | 约格子尺寸 `6%-8%` |

阴影规则：

- 首页、结果页按钮可以使用较明显柔和阴影。
- 关卡页按钮阴影应轻，避免压过棋盘。
- 棋盘本身优先靠边界和色块层次，不使用重阴影。

## 6. 棋盘视觉规范

棋盘是关卡页最高优先级内容。

必须满足：

- 棋盘保持正方形。
- 棋盘尺寸和起点使用整数像素对齐，避免小数像素错位。
- 每个格子保持独立圆角矩形。
- 普通格子、提示蒙层和动画缩放使用同一套格子坐标。
- 棋盘不能只依赖颜色区分区域。

间隔与边界：

- 每个格子的圆角留白也属于间隔层。
- 同一区域内相邻格之间的间隔露出白色棋盘底板，让每个格子保持独立圆角矩形。
- 不同颜色区域之间不画深色边界，只露出白色棋盘底板间距。
- 棋盘最外缘不画深色边框，只保留白色底板与页面背景的自然边界。
- 所有格子之间，包括同色内部、不同色交界和棋盘外缘，都不出现深色线。

### 6.1 棋盘无深色外框规范

棋盘不绘制黑色或深色外框，区域识别主要依靠白色格间距、独立圆角、颜色和底纹图案。

外框宽度：

| 棋盘尺寸 | 外框宽度 |
| --- | --- |
| 5x5-9x9 | `0px` |

通用约束：

- 外框线宽固定为 `0px`。
- 不能通过黑线、深色线或加粗线分割棋盘外缘或内部区域。
- 白色底板必须仍覆盖整个棋盘范围，让格间距和棋盘外缘保持干净。
- 不同颜色区域之间不画深色边界线；不能通过黑线、深色线或加粗线分割内部区域。
- 同一区域内部缝隙不画黑线，也不使用同区域原色填满；统一露出白色棋盘底板，避免真机上同色格合并成大色块。
- 9x9 棋盘格子更小，应优先保证底纹和白色间距可见，避免棋盘变“网格化”。

运行时实现统一映射到 `scripts/ui_tokens.gd`：

```gdscript
static func board_border_width(board_size: int) -> float:
	return 0.0
```

`scripts/game_board.gd` 只负责调用 token，不再独立维护另一套线宽数值。
主关卡和新手教程必须调用同一个边界绘制逻辑；教程单目标步骤的聚焦效果不得额外加深外缘颜色，相邻排除和同行同列排除阶段不绘制灰色引导蒙层。

### 6.2 棋盘触控手感规范

棋盘操作以移动端触屏体验为准，桌面鼠标只作为调试入口。触控必须稳定、可预期，不能因为 Android 兼容鼠标事件或系统双击标记导致一次点击被误认为两次。

必须满足：

- 单击空格只标记普通 X，不能误触发小狮子尝试。
- 双击找小狮子必须来自同一格的两次完整点击，且两次点击的间隔、位置偏移都在安全范围内。
- 触屏事件发生后，短时间内到达的兼容鼠标事件不得重复触发操作。
- 拖动开始后，只执行连续标记/取消普通 X，不再转成单击或双击。
- 已锁定小狮子、提示小狮子、开局小狮子和错误红 X 都不响应单击、双击或滑动修改。

验收注意：

- Godot 桌面鼠标测试只能证明基础逻辑，不能证明 Android 触控手感。
- Android 真机或模拟器上要连续测试：慢速单击、快速单击、正常双击、过快双击、跨格点击、滑动批量 X。
- 如果用户反馈“点一下像点两下”，必须优先检查触屏和兼容鼠标事件是否被重复处理，以及双击时间窗口是否过宽。

棋盘状态：

| 状态 | 视觉 |
| --- | --- |
| 空格 | 区域底色 |
| 普通 X | 半透明深色 X，可取消 |
| 已确认小狮子 | 小狮子国王贴图，锁定，不可单击/双击/滑动修改 |
| 提示小狮子 | 锁定的小狮子国王贴图，不加高亮圈 |
| 开局国王 | 锁定的小狮子国王贴图，播放轻微缩放提醒 |
| 错误红 X | 红色 X，锁定，不可修改 |
| 提示范围 | 非操作格覆盖半透明白灰蒙层，不闪烁 |

### 6.2 X 标记视觉规范

普通 X 和错误 X 必须在全部 10 种区域色上清楚可见，并保持一眼可区分。

普通 X：

- 主线使用 `ink`，alpha 为 `0.78`。
- 符号半径为格子尺寸的 `18%`，线宽为格子尺寸的 `4.6%`，最小 `3px`。
- 主线下面增加低透明度白色细描边，防止深蓝、紫色等深色区域吞没符号。
- 不增加实心底圈，避免普通排除标记过度抢眼。

错误 X：

- 主线使用深错误红 `#D92F42`，保持不透明。
- 符号半径为格子尺寸的 `22%`，线宽为格子尺寸的 `6%`，最小 `4px`。
- 主线下面使用 `#FFF7F8` 浅色描边，描边比主线宽至少 `2.5px`。
- 背后增加 `danger_red`、alpha `0.22` 的柔和圆形底晕，圆半径为格子尺寸的 `32%`。
- 错误 X 必须明显强于普通 X，但不能遮挡区域底色和棋盘边界。

X 属于基础可缩放符号，当前优先使用 Godot 自绘线条。若后续主题皮肤需要纹理化图案，再使用透明 SVG/PNG 贴图；贴图应保留相同尺寸比例和语义颜色。

### 6.3 开局小狮子与进度规范

- 关卡标题下方始终展示小狮子图标、进度条和 `已找到 / 本关总数`。
- 有开局提示小狮子时，先显示轻量浮层，文案同时说明本关总数和赠送的小狮子数。
- 浮层中的小狮子依次运动到对应棋盘格，落位后才显示锁定小狮子，并同步增加进度。
- 每个小狮子落位后播放一次轻微缩放回弹；最大尺寸不超过格子尺寸的 `72%`。
- 缩放只改变小狮子贴图尺寸，不放大格子绘制矩形，防止边缘格角色越过棋盘外框。
- 浮层期间拦截棋盘输入，全部小狮子落位后淡出并恢复操作。

## 7. 按钮规范

按钮优先使用大圆角卡片。

底部操作区建议两等分：

```text
[ 小狮子头像 ×3 ] [ 灯泡 ×3 ]
```

两个道具按钮统一使用紧凑横向结构：`48 × 48px` 图标在左，`20px` 剩余次数或金币价格在右；不显示“小狮子”和“提示”名称。按钮高度不低于 `88px`，两项等宽；小狮子直找和提示在免费次数耗尽后显示金币价格，完整名称保留在辅助说明和控件 Tooltip 中。

按钮状态：

| 状态 | 视觉 |
| --- | --- |
| 默认 | 白色或浅色卡片 + 清晰图标文字 |
| 强操作 | 品牌色或浅绿色强调 |
| 禁用 | 保留轮廓和可读文字，降低饱和度，不完全“消失” |
| 按下 | 轻微缩放或颜色加深 |

交互反馈：

- 点击按钮：轻微缩放。
- 使用提示：按钮可短暂亮起。
- 次数不足：不强打断，展示弹窗或 toast 占位。

## 8. 首页规范

首页目标是建立品牌感和进入当前关卡。

首页应包含：

- `color king` 主标题。
- 柔和蓝色主视觉。
- 首页中间的小狮子必须使用与通关成功页一致的胜利全身小狮子素材，不能使用普通格子里的头像小狮子。
- “开始关卡”主按钮。
- “新人引导”入口，用于调试/验收。

首页不显示：

- 金币、红心、星数。
- 排行榜、活动、宝箱。
- 底部导航。

## 9. 关卡页规范

关卡页目标是让玩家专注解题。

必须显示：

- 返回首页按钮。
- 当前持有金币。
- 本关独立红心体力槽。
- 设置入口。
- 选关入口。
- 当前关卡标题。
- 棋盘。
- 小狮子直找、提示按钮。

不应显示：

- 金币购买加号或促销横幅。
- 广告位。
- 排行榜/社交入口。

当前截图中的优先优化方向：

- 正式关卡移除黄色教练提示卡，将释放的纵向空间主要交给棋盘。
- 正式关卡提示道具仅通过棋盘蒙层、正常亮度格和可操作范围体现，不显示解释文字；提示范围只包含可单击画 X 的非小狮子空格。
- 提示蒙层使用半透明白灰色覆盖整个棋盘，包括格间接缝；随后重绘提示相关格和已有标记，避免逐格圆角蒙层产生接缝错位。
- 提示状态下仍不额外绘制区域深色线；正式关卡中全部保持明亮的提示目标格都可单击画 X，不使用实线框、光环或持续闪烁。
- 底部禁用按钮需要更像“暂不可用”，而不是“坏掉/丢失”。
- 棋盘最外缘不画深色线；不同颜色区域不依赖深色线区分，优先通过色块、白色间距、圆角和更明显的底纹保障色弱用户辨认。

### 9.1 新手教程布局

新手教程使用与正式关卡相同的页面骨架，不单独维护一套精简布局：

- 顶部保留首页、金币、红心和帮助入口，并用“跳过”替代“选关”。
- 正常显示“新手教程”标题、小狮子进度、教练提示卡和正方形棋盘。
- 底部保持小狮子直找、提示两等分布局，避免玩家进入正式关卡后重新识别工具位置。
- 强引导阶段不需要的道具保持可见但使用禁用态；提示和小狮子直找在对应教学阶段使用黄色强调，并由小手指向。
- 相邻排除和同行同列排除阶段保持整张棋盘原亮度，一次展示本阶段全部合法目标格；目标仅使用轻量金色细边，不使用灰色蒙层，并允许按住后连续滑过多个目标格标记 X。
- 教程中的小狮子直找生成与正式道具相同的锁定提示小狮子，但不扣除免费次数或金币；直找后根据棋盘现状继续引导尚未完成的规则排除。

### 9.2 多语言与 RTL

- 顶部设置使用与帮助按钮一致的 `46 x 46px` 点击目标，齿轮图标不依赖语言。
- 语言设置使用统一模态弹窗，选项以语言自身名称展示：English、中文、العربية、Français、Latina。
- 默认语言来自设备系统 locale；用户主动选择后由存档覆盖系统默认值。
- 所有静态控件通过 `LocalizationController` 注册到 Godot 翻译服务，动态数字文案调用控制器先翻译模板再格式化。
- 阿拉伯语将根界面方向切换为 RTL，顶部导航、弹窗和按钮顺序随继承方向镜像；棋盘坐标和关卡逻辑不镜像。
- 字体栈以 Noto Sans SC 为主字体、Noto Sans Arabic 为 fallback，打包产物必须同时包含两份字体和 OFL 许可证。
- 英语、中文、法语和拉丁语使用 LTR，不允许保留上一次阿拉伯语的布局方向。

## 10. 结果页规范

结果页使用蓝色主色系整屏结构。

成功页：

```text
顶部：完成文案
中部：胜利小狮子展位 / 奖励视觉
底部：[下一关] [主菜单]
```

失败页：

```text
顶部：挑战失败
中部：红心/失败反馈
底部：[重新挑战] [返回首页]
```

结果页不显示排行榜、广告、复杂奖励进度。

失败页不展示金币复活入口。红心用完后主按钮为“重新挑战”，副按钮为“返回首页”。

### 10.1 金币与付费提示视觉

- 顶部金币标签只显示图标和余额，不使用闪烁、红点或强促销动画。
- 顶部红心与金币标签同高；每颗红心保留至少 `32 × 38px` 独立空间，不允许通过压缩间距或字号适配。
- 有效红心使用红色实心图案，默认保持静止，不持续跳动；只有进入关卡、获得红心或失去红心时可播放一次短促心跳反馈。失去的红心立即恢复 `1.0` 比例、变为灰色实心图案并停止动画。
- 金币图标使用 `assets/ui/coin.png` 的透明 PNG 贴图，显示尺寸为 `28 × 28px`；不得退化为圆点字符或货币符号。
- 免费次数存在时，道具按钮显示 `×剩余次数`；免费次数耗尽后改为 `-金币价格`。
- 所有价格必须在点击前可见，扣款后余额立即刷新。
- 金币不足弹窗需要同时展示价格、当前余额和缺口。
- 激励广告按钮同时展示预计补币数量，且一次补币足以完成当前请求。
- 激励广告是玩家主动选择，不在开局、解题中途或通关后自动弹出。
- 当前购买与激励广告为接入占位；视觉上不得暗示已经到账。

## 11. 动效规范

动效目标是“轻快确认”，不是强刺激。

建议：

- 格子点击：`0.08-0.14s` 轻微缩放。
- 小狮子出现：`0.25-0.5s` 弹性缩放。
- 开局国王提示：轻微放大-回弹，不加金色光晕。
- 错误反馈：轻微震动或短闪，不长时间干扰。
- 通关反馈：棋盘轻闪 + 小狮子弹跳 + 结果页淡入。
- 红心动效只在状态变化时触发一次：`1.0 → 1.13 → 1.0 → 1.08 → 1.0`，结束后全部红心保持静止；失去的红心同尺寸变灰。

避免：

- 高频闪烁。
- 大面积强红警告。
- 长时间遮挡棋盘。

## 11.1 统一弹窗规范

所有模态弹窗使用游戏内绘制的全屏遮罩和圆角卡片，不直接依赖
`AcceptDialog`、`ConfirmationDialog` 等系统窗口外观。这样可以确保编辑器、桌面导出和移动端导出的标题栏、背景、边框与按钮保持一致。

弹窗基础视觉 token：

| Token | 用途 | 值 |
| --- | --- | --- |
| `dialog_scrim` | 全屏遮罩 | `#1A2438`，alpha `0.38` |
| `dialog_surface` | 弹窗背景 | `#FFFDF8` |
| `dialog_border` | 弹窗边框 | `#E7DED1` |
| `dialog_content_surface` | 富内容区块背景 | `#F7FAFF` |
| `dialog_content_border` | 富内容区块边框 | `#DFEAF6` |

弹窗卡片统一使用 `24px` 圆角、`2px` 边框，以及 alpha `0.16`、尺寸
`12px`、向下偏移 `5px` 的柔和阴影。内容左右内边距为 `24px`，上下内边距为
`20px`，区块间距为 `16px`。标准弹窗宽度为 `420px`，包含图片或复杂控件的富内容弹窗宽度为
`460px`；实际宽度不得超过视口宽度减 `48px`，高度不得超过视口高度的 `82%`。

标题和正文层级：

- 标题使用 `22px`、`ink`，左对齐。
- 主要正文使用 `16px`、`ink`。
- 次级说明使用 `14px`、`muted`。
- 信息类和帮助类弹窗可以显示右上角关闭按钮，点击区域不小于 `44 x 44px`。
- 需要用户明确选择的重要确认弹窗不依赖点击遮罩关闭。

按钮高度统一为 `48px`、圆角 `14px`、间距 `12px`。主按钮使用
`primary_blue` 和白色文字，次按钮使用 `#F1F4F7` 和 `ink`，不可逆操作才使用
`danger_red`。取消或次要操作在左，确认或主操作在右；三个操作时保持等宽，主操作仍位于最右侧。

交互与动效：

- 打开时遮罩淡入，卡片在 `0.18s` 内从 `0.96` 缩放到 `1.0`。
- 关闭时在 `0.14s` 内淡出。
- 遮罩拦截底层输入，点击弹窗外部默认不关闭。
- `Esc` 和移动端返回键执行取消或关闭。
- 打开后主操作按钮获得焦点。
- 同一时间只显示一个模态弹窗，新弹窗打开前收起旧弹窗。

弹窗统一支持信息、确认、多操作和自定义内容四种模式。帮助规则、关卡选择、跳过教程、恢复教程和金币不足提示都使用
`scripts/dialog_controller.gd`；toast 和教程中央提示属于非模态反馈，不纳入弹窗控制器。

### 12.1 规范如何落地到代码

`UI_DESIGN_GUIDE.md` 本身不会自动影响游戏运行，它的作用是把设计决策稳定下来。真正生效需要经过四层：

1. 文档层：在本文档中确定视觉规范。
2. Token 层：把共享规范同步到 `scripts/ui_tokens.gd`。
3. 代码层：页面和棋盘只引用 token 常量、样式函数或绘制参数。
4. 验收层：通过截图、真机测试和 smoke test 确认实现符合规范。

落地优先级：

```text
PRODUCT_REQUIREMENTS.md 约束玩法和产品事实
UI_DESIGN_GUIDE.md 约束视觉和交互表现
scripts/*.gd 决定运行时真实效果
tests/*.gd 保障关键行为不回退
```

### 13.1 打包 / 发布前 UI 视觉验收标准

只要本次改动涉及 UI、视觉素材、动效、音效反馈、页面布局、棋盘绘制、按钮状态、提示蒙层或结果页，打包、发布新功能或交付新版本前必须执行本节验收。

修改前必须先对照本规范、`docs/PRODUCT_REQUIREMENTS.md`、`README.md` 和 `AGENTS.md`，列出受影响页面、组件、测试和文档，并在用户确认后再开始修改。修改后必须同步更新这些文档；如果某项不需要更新，交付说明中要说明原因。

验收原则：

- 不把“自动测试通过”等同于“视觉符合规范”。
- 不把“核心规则大体一致”等同于“和规范图一致”。
- 没有真机截图或同尺寸运行截图时，只能给出“代码层 / 模拟层通过”的结论，不能宣称真机视觉已通过。
- 项目内提供 `tools/capture_ui_screenshots.gd` 生成 540×960 移动端尺寸运行截图；它用于快速发现 UI 偏差，但不能替代 Android 真机 APK 截图。
- 发现视觉差异时必须明确列为“不一致项”，不能用笼统描述掩盖。
- 所有规范示意图和验收截图优先使用原尺寸展示；如果必须缩放，需说明缩放比例，并检查缩放前原图。

最低验收页面：

| 页面 / 状态 | 必查内容 |
| --- | --- |
| 首页 | `color king` 标题、胜利小狮子主视觉、开始关卡、新人引导、蓝色主色系、无多余金币/红心/排行榜入口 |
| 正式关卡页 | 顶部金币/红心/帮助/设置/选关、关卡标题、进度条、棋盘、底部“小狮子/提示”两按钮、无清除/撤销按钮 |
| 棋盘空态 | 白色底板、独立圆角格、所有格子之间白色格间距、不同色之间无深色分割线、无深色外框、10 色色板、底纹可见度 |
| 棋盘标记态 | 普通 X、正确小狮子、提示小狮子、开局小狮子、错误红 X 的尺寸、居中、锁定状态和可读性 |
| 正式提示 / 新人引导 | 正式提示仍使用非目标格半透明白灰蒙层；新人引导的相邻与行列排除不使用蒙层，本阶段全部合法目标格同时显示金色细边并支持连续滑动 |
| 通关结果页 | 蓝色整屏结构、成功文案、胜利小狮子全身图、下一关、主菜单、无排行榜/广告/奖励进度 |
| 失败页 | 蓝色整屏结构、失败文案、低头流泪小狮子、重新挑战、返回首页 |
| 弹窗 / 设置 | 游戏内统一遮罩和圆角卡片、按钮可读、中文/英文/阿拉伯语/法语/拉丁语文案不裁切 |

棋盘视觉必须逐项打勾：

- 棋盘最外缘不出现黑线或深色外框。
- 棋盘外缘仍保持白色底板和独立格子的干净边界，不出现方形硬边或断线。
- 不同颜色区域之间不出现深色边界线；只通过白色格间距、圆角、颜色和底纹区分。
- 同色区域内部和不同色交界都不画深色线，也不填成同色大块；必须能看出每个格子的白色间距和圆角。
- 每个格子等宽等高，图标、X、底纹和蒙层不能撑大或改变格子尺寸。
- 底纹在真机上应比旧版更可见但不抢眼；不能完全消失，也不能影响 X/小狮子辨认。
- 小狮子在格子中居中，视觉尺寸接近规范，不越过格子边界。
- 普通 X 和错误红 X 都居中；普通 X 可取消，错误红 X 不可修改。
- 提示蒙层让非提示区域“像被盖住一层白灰”，不能把原本颜色变成脏暗色，也不能完全看不出原颜色。

验收输出格式：

```text
UI 验收结论：
- 通过项：
- 不一致项：
- 未能验证项：
- 使用截图 / 设备 / 包版本：
- 是否允许打包或发布：
```

如果存在未解决的不一致项，默认不得宣称“已与 UI 规范一致”。只有用户明确接受差异，或代码修正并重新截图验收后，才能进入打包或发布。

每次发布至少捕获以下稳定检查点，文件名应包含页面、环境和时间：

- `home`：首页静态态。
- `tutorial`：教程首步及教程提示态。
- `level`：正式关卡空态。
- `board_marks`：普通 X、正确小狮子和错误红 X。
- `hint`：正式提示蒙层与可操作目标。
- `success`：成功结果页。
- `failure`：失败结果页。
- `dialog_zh`、`dialog_en`、`dialog_ar`：弹窗和多语言布局。

基准管理规则：

- `docs/prd_screenshots/*_runtime.png` 是经产品和设计确认的 V1 基准；更新基准属于产品/UI 变更，必须说明原因并经用户确认。
- 当前截图与基准必须使用相同视口、语言、关卡、存档和状态；动态动画应在稳定帧停止后截图。
- 像素差异只用于发现变化。字体抗锯齿、GPU 和平台渲染可能产生合理差异，最终必须按本规范人工复核关键区域。
- 差异报告必须保留当前图、基准图、差异图或差异说明，不能只保存“通过”文本。
- 未生成基准的页面按“首次基准候选”处理，不能自动判定通过。

线上或联机设备要求：

- 本地真机优先使用 USB ADB；无线设备使用配对后的 Wi-Fi ADB；云真机必须能安装指定 APK、回传原始截图并记录设备型号。
- 报告必须记录 APK SHA-256、包生成时间、设备型号、Android 版本、逻辑分辨率、连接方式和测试时间。
- V3 至少执行 PRD 中所有标记 `D` 的 P0 用例；滑动、双击、返回键、RTL、音效和动效必须实际操作，不能只看截图。
- 网络或设备不可用时允许完成 A/V 层验证，但发布状态必须为“待真机验收”。
